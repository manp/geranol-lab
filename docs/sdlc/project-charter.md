# منشور پروژه — سامانهٔ آزمایشگاه گرانول

> **وضعیت: پیش‌نویس ۰.۱ (Sprint 0)** — پس از دریافت نتایج پرسشنامهٔ مشتری به نسخهٔ ۱.۰ ارتقا می‌یابد.

## ۱. هدف

ساخت سامانهٔ وب جامع برای آزمایشگاه گرانول شامل وب‌سایت عمومی (معرفی و خدمات) و پنل مدیریت جامع (مدیریت آزمایش‌ها، ثبت گزارش، پاسخ آنلاین آزمایش‌ها، پرداخت آنلاین) به‌طوری‌که مشتری بتواند نتیجهٔ آزمایش خود را در پنل شخصی ببیند.

## ۲. ذی‌نفعان

| ذی‌نفع | نقش در پروژه |
|---|---|
| مدیر آزمایشگاه (مشتری) | مالک محصول؛ پاسخ‌دهندهٔ پرسشنامه؛ تأیید نهایی |
| کارکنان آزمایشگاه | کاربر پنل مدیریت (پذیرش نمونه، ثبت نتیجه) |
| مراجعان/مشتریان آزمایشگاه | کاربر پنل مشتری (پیگیری، نتیجه، پرداخت) |
| استاد و تیم توسعه | تحلیل، طراحی و پیاده‌سازی |

## ۳. محدودهٔ اولیه (از اعلام مشتری — نیازمند تأیید پرسشنامه)

- وب‌سایت عمومی: معرفی آزمایشگاه، صفحات خدمات/آزمایش‌ها، تماس
- پنل مدیریت جامع: مدیریت آزمایش‌ها، ثبت گزارش، مدیریت داخلی
- پاسخ آنلاین آزمایش‌ها و انتشار نتیجه در پنل مشتری
- پرداخت آنلاین
- فناوری: Laravel + کتابخانه‌های CSS فارسی؛ رابط کاربری فارسی (RTL)

## ۴. خارج از محدوده (فعلاً)

- اپلیکیشن موبایل بومی
- اتصال مستقیم به دستگاه‌های آزمایشگاهی (LIS) — در پرسشنامه پیگیری می‌شود

## ۵. محدودیت‌ها و فرض‌ها

- توسعه با SDLC استاندارد + تکنیک اسکرام روی GitHub (Issue، Milestone، PR)
- میزبانی و دامنه: در پرسشنامه مشخص می‌شود (پیش‌فرض: زیرساخت nsar.ir)
- درگاه پرداخت: پس از انتخاب مشتری

## ۶. ریسک‌های اولیه

| ریسک | اثر | پاسخ |
|---|---|---|
| ناقص بودن نیازمندی‌ها | بازکاری | پرسشنامهٔ ساخت‌یافته + تأیید منشور پیش از طراحی |
| تنوع قالب گزارش‌های آزمایش | پیچیدگی فرم‌ها | طراحی فرم پویا بر اساس نوع آزمایش |
| تأخیر در دسترسی درگاه پرداخت | مسدودشدن Epic پرداخت | پیگیری مجوز و درگاه در Sprint 0 |

## ۷. معیارهای موفقیت

- مدیر آزمایشگاه چرخهٔ «پذیرش نمونه ← ثبت نتیجه ← اطلاع مشتری» را بدون ابزار خارجی انجام دهد.
- مشتری بدون مراجعهٔ حضوری، نتیجه را ببیند و هزینه را پرداخت کند.
- رابط کاربری کاملاً فارسی، ساده و موبایل‌پسند.
